# Wave 3 — UI shell

**Goal.** An analyst’s desk, not a ChatGPT clone.

**Depends on.** Wave 2 (brief SSE works via curl).

**Exit (P0 product).** The 3-minute path works except fancy PDF highlight. Screenshot it. Do not start Wave 4 until this path is boringly reliable.

**App:** `apps/web` Next.js App Router, TypeScript. Talk to the API only through `src/lib/api.ts` (typed). No raw `fetch` in components.

---

## Design constraints

- Three panes: **library | reader | briefing**
- Editorial type, paper-like reader, quiet chrome
- No gradients, no marketing hero, no auth wall
- Footer disclaimer: “Not medical advice. Not a clinical system. Answers are grounded only in the loaded dossier.”
- Desktop first (1280+). A usable stacked layout on narrower screens is enough; do not spend a day on mobile.

Suggested tokens (implement, do not cargo-cult a UI kit):

- Background: warm paper / ink, not default shadcn purple
- One accent for chips and the active document
- Reader column is the visual centre

## Phase 3.2 — Library and ingest UX

### Library pane

For each document: filename, status, chunk count, page count.

Statuses map to human copy:

| status | Copy |
|---|---|
| queued | Waiting |
| parsing | Reading pages |
| chunking | Splitting passages |
| embedding | Indexing |
| ready | Ready |
| failed | Could not read (show `error_code` in plain language) |

`unreadable_pdf` → “This PDF has no text layer. Dossier does not OCR scanned pages.”

### Actions

- Drop zone + file picker: PDF, MD, TXT
- “Load seed corpus” button → `POST .../seed`, then refresh list
- After upload, poll `GET /documents/{id}` every 500ms until `ready` or `failed` (v1 is sync so one refresh may suffice — still poll so the UI survives a later async change)

### Acceptance

- [ ] Seed + upload appear without a full page reload
- [ ] Failed scanned PDF shows the OCR copy, not a toast “Error”

## Phase 3.3 — Briefing stream and citation chips

### Thread

- User bubble: question
- Assistant: streamed tokens from `event: token`
- On `event: final`:
  - Replace/confirm text from `final.text` (so verify/refuse can rewrite)
  - Render chips from `final.citations` **only**
  - Subline: “Based on N passages” or “Not in this dossier”

### Chips

Click → `GET /chunks/{id}` → reader shows filename, page range, text. For MD/TXT, highlight the chunk string (`mark` or equivalent). PDF page jump is Wave 4.

Ignore any cite the model streamed in prose that is not in `final.citations`.

### Help

Seed the composer placeholder with two examples:

- Answerable: “What is the recommended dose?”
- Unanswerable: “Is there any X-ray related document?”

### Conversation

Send `conversation_id` from the first `final` (or a create-conversation call) so follow-ups have history. If the API returns it on `final`, store it in React state.

### Acceptance

- [ ] Reviewer can seed → ask → see chips → click → read the passage
- [ ] Unanswerable question shows the refusal copy
- [ ] Screenshot: library + brief + chip selected
- [ ] No cite chip exists that 404s on `/chunks/{id}`

**Wave 3 exit.** P0 product. Wave 4 is polish and engineering story, not “make it work.”
